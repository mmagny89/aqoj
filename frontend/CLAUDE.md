# Règles du front — À quoi on joue

React 18, Vite 6, Tailwind v4 (plugin `@tailwindcss/vite`, configuration dans le CSS), React Router 6. Servi par Vite en dev derrière Caddy ; l'API est appelée en relatif (`/api`).

- Appels API : `src/api.js` uniquement (jeton `aqoj_token` dans `localStorage`, redirection vers `/connexion` sur 401).
- Lint : `npm run lint` ; `react-hooks/set-state-in-effect` est en avertissement (chargements lancés depuis un effet : à refondre page par page), tout le reste doit passer.
- Tests : Vitest + Testing Library (`npm test`), requêtes par rôle ou texte visible plutôt que par classe CSS ; `src/test/setup.js` nettoie le DOM et le `localStorage`.
- Aucune ressource externe chargée par l'application, hors images des jeux (CDN `*.geekdo-images.com`, autorisé par la CSP de Caddy).
- Les pages affichent des données déjà calculées par l'API : pas de logique de recommandation ou de rareté côté React.
- Thème « plateau » (charte du site de l'association, projet `../edj`, `app/assets/styles/site.css`) : jetons dans `src/index.css` (`@theme`), pas de couleur écrite en dur dans un composant. Utilitaires `bg-paper`, `bg-brand-red|yellow|blue|green`, `text-ink`, `border-ink`, `bg-board` ; composants `.panel`, `.token-card`, `.btn` (+ `.btn-primary` rouge, `.btn-secondary` jaune), `.chip` (`aria-pressed`), `.badge`. Bord d'encre de 3 px, ombre dure décalée. Les rampes `stone` et `amber` de Tailwind sont redéfinies sur la charte, et `white` vaut le papier : une ancienne page garde ses classes et prend la charte.
- Contraste : jamais de texte blanc sur le rouge vif `#fb5a48` (3,2 : 1) ; encre sur le rouge (5,6 : 1). Les boutons pleins hérités tirent sur `amber-500` (rouge profond, 5,3 : 1).
- Polices auto-hébergées par `@fontsource` (Akaya Kanadaka pour les titres, Atkinson Hyperlegible pour le texte), importées dans `main.jsx` ; la CSP n'autorise que `font-src 'self'`, donc `assetsInlineLimit: 0` dans `vite.config.js` (une police ne devient jamais une URL `data:`). Un fichier ajouté à `public/` exige de relancer `docker compose --profile frontend restart node`.
- Coque : `components/AppShell.jsx` (rail latéral dès 1024 px, barre d'onglets en bas en dessous, recherche en haut, lien d'évitement). Une page ne pose ni `pt-16` ni pied de page. Toutes les pages sont au nouveau style : une page neuve suit le même modèle, sans emoji décoratif (seuls ceux des thèmes de l'admin, qui sont de la donnée). Champs de formulaire : `components/forms.jsx` (`Field` et `SelectField` relient libellé et champ, `ErrorMessage`, `AuthCard`) ; un tableau large défile dans sa boîte (`relative overflow-x-auto`), une fenêtre modale a `role="dialog"`, `aria-modal` et se ferme à Échap. Modèle d'une page : `mx-auto max-w-7xl px-4 sm:px-6 lg:px-10`, un `h1` Akaya, sections en `.panel`, listes de cartes en `<ul>`, filtres en `.chip`. Une carte de jeu est `GameCard` (lien étiré sur toute la carte, bouton d'action au-dessus) ; cibles de 44 px au moins.
- Import : `pages/ImportPage.jsx` (onglets `?onglet=bgg|myludo|parties`, un onglet est un composant : `ImportBggTab`, `ImportMyLudoTab`) ; un administrateur choisit la destination (sa ludothèque ou celle de l'association) et `key={cible}` remonte l'onglet pour repartir d'un état vide. Le rapprochement MyLudo se fait côté API : l'interface ne fait que choisir parmi des candidats ou chercher (`GamePicker`, recherche locale).
- `components/TasteForm.jsx` est le questionnaire de goûts, dans `AccountPage` seulement (`allowEmpty` pour effacer) : l'accueil n'en porte plus, il invite à le remplir par `TasteInvite` tant que rien n'est déclaré ; un jeu ne s'affiche qu'une fois sur l'accueil (dédoublonnage dans `HomePage`). La table de l'accueil s'enregistre à chaque clic (`saveTable`), et les idées « pour votre table » ne se chargent qu'une fois la table retrouvée.
- Tests : après la suite PHP, Vitest peut dépasser ses délais sur quelques fichiers (« Timeout terminating forks worker ») ; relancer seul `npx vitest run` avant d'y voir une régression.
- Accueil : le sélecteur de périmètre (« Ludothèque de l’asso et des membres » par défaut, « Tout le catalogue »), mémorisé dans `localStorage` (`aqoj_perimetre`), pilote `home-reco` et `home-tonight` (`scope`). Nouveautés, oubliés et époques sont les onglets de `DiscoverTabs` (un onglet absent quand il n'a rien à montrer ; « Oubliés de la ludothèque » disparaît en « Tout le catalogue ») ; « Par époque » garde ses onglets de décennie.
- Filtres fins : `.chip chip-sm` (28 px visibles, zone tactile de 44 px par un `::after` sur la hauteur) pour la table et le périmètre de l'accueil, rangés par `FilterRow` (libellé et puces sur une ligne) ; plus de mascotte sur l'accueil.
- « À quoi on joue » (`/recommander`, `RecommendationPage`) : pas de bouton, les résultats se rechargent seuls (250 ms de latence) à chaque changement de table, de style ou de thème ; trois onglets `collection` (Dans ma ludothèque), `library` (À l'association), `discover` (Tout le catalogue), chacun avec son compte. À l'ouverture : styles favoris présélectionnés (visibles et décochables dans « Style / Moteur », sans bloc à part) (goûts déclarés puis déduits) et table enregistrée.
- Onglets et sous-onglets se distinguent : un **onglet** (`role="tab"`) est une languette posée sur un filet d'encre (`.tab-list` + `.tab`, 44 px, sélection par `aria-selected`) ; un **sous-onglet** ou un filtre est une puce fine (`.chip .chip-sm`, `aria-pressed` ou `aria-selected`). Jamais deux rangées de puces de même taille l'une sous l'autre.
- Explorer (`SearchPage`) : bandeau jaune (`bg-brand-yellow`) qui réunit titre, recherche et filtres en rangées `FilterRow scroll` (composant partagé avec l'accueil ; sur téléphone la rangée défile au lieu de passer à la ligne : 284 px au lieu de 782). Filtres masqués dès qu'un nom est saisi.
